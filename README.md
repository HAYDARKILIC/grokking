# Grokking on the Weight-Decay Clock — nonlinear test of two exact identities

Code, data summaries, figures and tables for a study that tests two exact,
constant-free identities for delayed generalization in a **nonlinear** network.
The identities had previously been verified only in exactly solvable linear
models, from single seeds, and with no measurement of the remainder their
nonlinear extension incurs.

> This repository contains **no manuscript text**. It exists so that reviewers
> and editors can inspect the code, the recorded results and the artwork
> independently of the paper.

## What was run

A four-phase full factorial grid, **351 runs, 12.21 accelerator-hours**, on one
NVIDIA A100-SXM4-40GB, entirely in IEEE binary64 with TF32 disabled.

| Phase | Question | Runs |
|---|---|---|
| A | Does the reference benchmark reproduce? | 1 |
| B | How far do the reported values move across seeds and architectures? | 216 |
| C | Does the optimizer-dependence identity (P4) hold? | 64 |
| D | Does the intervention identity (P2) hold, and how large is the remainder? | 70 |

Task: addition modulo *p* with concatenated one-hot inputs. Model: bias-free
two-layer perceptron with quadratic activation, `f(x) = ((x W1)^2) W2`,
P = 6,528 parameters at the reference configuration, trained in full batch by
heavy ball with weight decay.

| (P4) confirmed within interval | β ∈ {0, 0.5}; exceeded by 36 % and 17 % at β ∈ {0.9, 0.95} |
| Drift law | δ(c) = K(c−1)², K = **0.0893**, varying 1.1 % while δ spans nearly three orders of magnitude |
| Frozen-projector validity horizon | **21 %** of the mean *k*_grok |

| Delay ratio across architectures | cell means from 1.33 to 170.33 |
| Right-censored | 72 of 216 Phase B runs (all at p = 31) |

The full run log (`runs.jsonl`, 351 records with complete trajectories,
144,985,738 bytes, SHA-256 `b4806d10…c2b01f80`) is too large for version control.
`results/runs_summary.csv` carries every per-run scalar; the trajectories are
regenerated by re-running the notebook, and the digest above lets anyone verify
a copy obtained separately.

## Reproducing

```bash
pip install -r requirements.txt
jupyter lab notebooks/grokking_wd_clock.ipynb
```

Set `SMOKE_TEST = True` first: it exercises the whole pipeline in a few minutes.
Then set it to `False` for the full grid. Every completed run is appended to
`runs/runs.jsonl` and flushed, and re-running skips configurations already
present, so an interrupted session resumes rather than restarts.

A CUDA device is optional. The model is small enough that a single CPU core is
competitive — about 360 µs/step against roughly 1 ms/step on an A100, where
kernel-launch latency dominates. **However**, CPU and GPU execution are not
interchangeable for this phenomenon: floating-point reduction order is known to
flip individual seed outcomes. Do not merge results obtained in different
numerical environments.

## Caveat on `cpu_scout_p4_initscale.jsonl`

This 54-run file is a **scouting result, not manuscript data**. It was produced
on CPU to check, before spending GPU time, whether the (P4) deviation survives
a change of initialization scale. It does: the excess over the prediction is
+38.7 %, +12.7 % and +14.7 % at β = 0.9 for s = 1.0, 1.5 and 2.5 respectively.
`s = 1.5` was re-run on CPU as an internal bridge so the scale comparison is
environment-consistent. These numbers must not be pooled with the A100 grid.

## Known limitations

- Single task family (modular addition), squared loss, full batch, quadratic
  activation. The quadratic activation makes the theory's local expansion exact
  to the order it uses, so the results are an **upper bound** on transferability.
- The initialization scale `s = 1.5` is calibrated against the three independent
  landmarks, not quoted from the source. Phases C and D ran at that value only.
- All 72 runs at p = 31 are right-censored at the 400,000-iteration ceiling.
- The Phase D projector is built at one reference iteration, k₀ = 1000.
